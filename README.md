# 따릉이 대여소 군집 관제 화면

가중치를 바꾸면 군집이 어떻게 달라지는지, 그리고 각 군집·대여소가 실제로
어떤 지표를 갖는지를 지도에서 확인하는 교육용 화면이다.
HTML + CSS + 바닐라 JavaScript + Leaflet만 쓴다. 서버 프레임워크도, 빌드
도구도, API 키가 필요한 지도 서비스도 쓰지 않는다.

## 4. CSV가 보이지 않을 때 확인할 것

화면 상단 띠에 빨간 안내가 뜨거나 대여소 수가 `—`로 남아 있으면 순서대로 확인한다.

1. **`file://`로 열었는가** — 주소창이 `http://localhost:8000`인지 본다. 가장 흔한 원인이다.
2. **명령을 실행한 폴더가 맞는가** — `dashboard` 폴더에서 실행해야 한다. 한 단계
   위에서 실행했으면 주소가 `http://localhost:8000/dashboard/` 가 된다.
3. **파일이 있는가** — `dashboard/data/bike_station_profile.csv` 가 실제로 있는지 본다.
   없으면 `실습/05주차/05주차_데이터셋/data/bike_station_profile.csv` 를 복사한다.
4. **포트가 이미 쓰이는가** — `python -m http.server 8000` 이 "Address already in use"로
   실패하면 `python -m http.server 8001` 로 바꾸고 URL도 8001로 바꾼다.
5. **파일 인코딩** — CSV는 UTF-8(BOM 포함)이다. 엑셀에서 다시 저장하면서 ANSI/CP949로
   바뀌면 대여소명이 깨진다. 다시 복사해온다.
6. **브라우저 개발자도구(F12) → Console** 에서 빨간 오류를 확인한다. 화면 상단 띠에도
   같은 내용이 요약돼 나온다.

## 5. Leaflet CDN·지도 타일이 보이지 않을 때 확인할 것

- **지도 자리가 통째로 비어 있고 +/− 버튼도 없다** → Leaflet 자체를 못 불러왔다.
  `unpkg.com` 접근이 막혔을 가능성이 크다. 사내망·교육장 방화벽에서
  `unpkg.com` 을 허용하거나, `leaflet.js` / `leaflet.css` 를 내려받아
  `index.html`의 CDN 주소를 로컬 경로로 바꾼다.
- **점은 보이는데 배경 지도만 회색이다** → 타일만 못 불러온 것이다. 지도 아래에
  안내 문구가 뜬다. `tile.openstreetmap.org` 접근을 확인한다.
  **배경이 없어도 점의 좌표·색·군집 계산은 모두 정상이다.** 수업은 그대로 진행할 수 있다.
- **점도, 지도도 안 보인다** → 4절(CSV)을 먼저 확인한다. 데이터를 못 읽으면 지도도
  그리지 않는다.
- 오프라인 교육장이라면 미리 접속해서 타일을 캐시에 올려두거나,
  `screenshots/` 의 이미지를 대체 화면으로 쓴다.

## 6. 가중치가 군집에 반영되는 계산 방식

버튼을 누르면 아래 순서를 그대로 다시 실행한다. 사전 계산 결과를 불러오는 것이
아니라 브라우저에서 매번 새로 계산한다.

1. **결측치·무한대 확인** — 군집 변수 5개와 위도·경도에 `NaN`/`Infinity`가 있는 행을
   빼고 센다. 현재 데이터에는 없어서 2,782곳 전부 쓴다(상단 띠에 표시).
2. **변수별 평균·표준편차** — 모집단 표준편차(ddof=0)를 쓴다. scikit-learn
   `StandardScaler`와 같은 계산이다.
3. **표준화** — `z = (원본값 − 평균) ÷ 표준편차`
4. **가중치 적용** — 아래 식.
5. **KMeans k=4 재실행** — 브라우저에서 다시 돌린다.
6. **군집별 원본 지표 평균 재계산** — 표준화값이 아니라 원래 단위로 되돌린 평균.
7. **지도·군집 요약·대여소 목록 갱신**

### ★ 표준화값 × √(정규화 가중치)

쓰려는 거리는 가중 유클리드 거리다.

```
거리² = Σ_j  w_j × (z_aj − z_bj)²          w는 합이 1인 정규화 가중치
```

KMeans는 입력 좌표에 대해 그냥 유클리드 거리를 쓴다. 그래서 입력 좌표를

```
x_j = z_j × √w_j
```

로 만들어 넣는다. 그러면 `(x_aj − x_bj)² = w_j × (z_aj − z_bj)²` 가 되어
원하는 거리와 정확히 같아진다.

> **`z_j × w_j` 로 넣으면 안 된다.** 그러면 거리에 `w_j²` 가 곱해져서
> 가중치가 제곱으로 반영된다. 20%를 40%로 두 배 올렸을 때 거리 기여가
> 네 배가 되어, 화면의 슬라이더 숫자와 실제 영향이 어긋난다.
> 이 화면은 `applyWeights()`에서 `Math.sqrt(normalized[j])`를 곱한다.
> 검수 스크립트가 이 값을 직접 다시 계산해 대조한다(`√w`와는 차이 0,
> `w`와는 차이 0.63).

화면 왼쪽 표는 세 값을 구분해서 보여준다.

| 열 | 뜻 |
| --- | --- |
| 입력값 | 슬라이더에 넣은 값. 합계가 100%가 아니어도 된다 |
| 유효 가중치 | 합계 100%로 다시 나눈 값. 실제 `w_j` |
| 거리 배율 √유효가중치 | 표준화값에 곱해지는 실제 배율 |

합계가 50%든 250%든 결과는 같다. 비율만 같으면 같은 군집이 나온다.
(검수 항목: 각 10%(합계 50%) 입력이 각 20%와 군집 변경 0곳으로 동일)

### KMeans 조건

| 항목 | 값 |
| --- | --- |
| k | 4 고정 |
| 초기 중심 | 고정 시드 LCG를 쓴 k-means++ (`Math.random` 미사용) |
| 시작 횟수 | 서로 다른 고정 시드 5개로 돌려 inertia 최소인 결과 채택 |
| 최대 반복 | 100회 |
| 수렴 조건 | 라벨 변화 0 **또는** 중심 이동 제곱합 < 1e-9 |
| 빈 군집 처리 | 자기 중심에서 가장 먼 점을 그 군집으로 옮긴다(2곳 이상인 군집에서만 뺏는다) |

시드가 고정이라 **같은 데이터·같은 가중치면 몇 번을 눌러도 같은 결과**가 나온다.
기본 가중치 결과는 scikit-learn `KMeans(n_clusters=4, random_state=42, n_init=20)`
과 같은 해에 도달한다(inertia 7086.33).

## 7. 군집 번호·색상 정렬 방식

KMeans가 내놓는 번호에는 아무 뜻이 없다. 그대로 쓰면 가중치를 조금 바꿀 때마다
색과 번호가 통째로 뒤바뀌어서, 실제로 바뀐 것이 무엇인지 볼 수 없다.
그래서 두 단계로 번호를 고정한다.

**(1) 기본 가중치 결과의 번호를 고정한다.** 원본 평균만 보고 정한다.

| 규칙 | 번호 |
| --- | --- |
| 일평균이용건수 평균이 가장 큰 군집 | 1 |
| 남은 셋 중 출근시간비중 평균이 가장 큰 군집 | 3 |
| 남은 둘 중 퇴근시간비중 평균이 가장 큰 군집 | 0 |
| 마지막 남은 군집 | 2 |

발표자료 `발표자료/10_국내데이터분석실전_13~16일차/클러스터링_표준화와_의미해석_발표자료.pptx`
의 군집 번호와 같아지도록 맞춘 규칙이다. 수업 중 슬라이드와 화면이 같은 번호를
쓰게 하는 것이 목적이다.

**(2) 가중치를 바꾼 결과는 기본 중심에 최소거리로 맞춘다.**

- 새 중심을 `√w` 로 나눠 **표준화 공간으로 되돌린 뒤** 기본 중심과 비교한다.
  가중치가 다르면 좌표 축척이 달라서 그대로 비교할 수 없다.
- k=4이므로 4! = **24가지 순열을 전부 계산해 거리합이 최소인 배치**를 고른다.
  하나씩 가까운 것부터 붙이는 그리디가 아니라 최적 매칭이다.
- 화면 상단 띠에 실제로 적용된 매칭이 `매칭 2→3→0→1` 형태로 표시된다.
  (원래 0번이 2번으로, 1번이 3번으로 … 바뀌었다는 뜻)

**이 방식의 한계 — 반드시 알고 써야 한다.**

- 가중치를 크게 바꾸면 군집의 성격 자체가 달라진다. 그때 "가장 가까운 기본
  군집"에 붙인 번호는 **연속성의 힌트일 뿐 같은 그룹이라는 보장이 아니다.**
  예를 들어 출근 가중치를 80%로 올리면 군집 2와 3이 모두 "출근 집중형 후보"가
  된다 — 번호는 이어졌지만 내용은 달라졌다.
- 군집이 쪼개지거나 합쳐지는 경우(하나가 둘로 갈라짐)를 1:1 매칭으로는
  표현할 수 없다. 이때는 번호가 아니라 **카드의 원본 평균과 대여소 수**를 봐야 한다.
- 그래서 화면은 번호만 쓰지 않는다. 항상 번호 + 업무용 이름 후보 + 대여소 수를
  함께 표시하고, 색만으로 군집을 구분하지 않는다.

## 8. 조작 방법

| 하고 싶은 것 | 방법 |
| --- | --- |
| 가중치 바꾸기 | 슬라이더를 끌거나 오른쪽 숫자칸에 직접 입력 |
| 다시 계산 | **군집 다시 계산** 버튼. 버튼을 누를 때만 KMeans가 돌아간다 |
| 기본값으로 | **기본값으로 초기화** 버튼 (각 20%) |
| 특정 군집만 보기 | 지도 위 `전체 / 군집 0~3` 칩, 또는 오른쪽 군집 카드 클릭 |
| 대여소 찾기 | 오른쪽 검색칸에 대여소명 또는 대여소번호 입력 |
| 대여소 상세 보기 | 목록에서 클릭 (지도가 그 위치로 이동) 또는 지도에서 점 클릭 |
| 키보드로 목록 이동 | 목록에 포커스를 준 뒤 ↑ ↓ |

- 대여소 목록은 화면 성능을 위해 **일평균 이용건수 상위 300곳**까지만 보여준다.
  지도에는 2,782곳 전부 그린다. 목록 상단에 실제 해당 건수가 표시된다.
- 점 크기는 일평균 이용건수(제곱근 비례)다. 색은 군집이다.

## 9. 현재 데이터로 말할 수 없는 것

- **군집은 순위가 아니다.** 군집 1이 군집 0보다 좋거나 급이 높은 게 아니다.
  운영 유형을 탐색하기 위한 그룹이다.
- **업무지구·주거지·관광지라고 단정할 수 없다.** 데이터에 대여소 주변 시설 용도가
  없다. 출근시간 이용이 많다는 관찰만 있다. 그래서 화면의 이름은 모두 "후보"다.
- **실제 품절 원인을 알 수 없다.** 데이터에 실시간 재고·대여 실패·반납 실패가 없다.
  "자전거가 없어서 못 빌린 횟수"는 이 파일에 존재하지 않는다.
- **지도에 점이 몰려 있다는 것이 곧 운영 우선순위는 아니다.** 위치는 지도에서,
  중요도는 지표에서 본다.
- **비중 세 개를 더해 100%가 되지 않는다.** 출근·퇴근은 평일 기준, 주말은 요일
  기준이라 구간이 겹친다. 분모는 모두 그 대여소의 전체 이용건수다.
- **k=4는 주어진 조건이다.** 군집을 몇 개로 나누는 게 맞는지는 이 화면이 답하지 않는다.
- 관측일수가 짧은 신설 대여소는 비중이 크게 튈 수 있다. 최댓값이 100%인 비중 행이
  실제로 있다(걸러내지 않았다).
